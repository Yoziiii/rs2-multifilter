# 安装、升级、卸载与回滚

本安装文档对应 0.9.0 发行构建，功能实现沿用已验收 RC。正式包已生成且许可内容已核对，尚未公开上传；RC 验证记录及客户端检查豁免保留，不声称重新完成正式包的游戏内实测。

## 安装与升级

1. 备份世界、原 JAR、实例配置。专服先正常保存并停止。
2. 使用 Java21 / MC1.21.1 / NeoForge21.1.248 / RS2.0.9。客户端和专服均装本模组及 RS，本模组使用同一构建，不是纯客户端插件。
3. mods 内只留一份本模组；把旧 JAR 移到 mods 之外备份，不能仅在 mods 内改另一个 `.jar` 名称。
4. 基础功能不需 Create/JEI。可选组合见 [DEPENDENCIES.md](DEPENDENCIES.md)，不要混装 Forge/Fabric 包。
5. 先在测试世界启动，合成/打开卡片，保存分类、四槽取放并重新打开；专服还要实际入服，Done 不代替联机验收。

## 使用与异常恢复

主手右键打开；无自定义分类时准备一个默认分类。“全部”只是终端视图，不是分类数据。Ghost 样本不消耗物品；滚轮选候选不自动加规则；编辑后保存再安装。

未知/损坏卡保留原卡和副本，记录诊断，不当空白反复保存/复制。合法旧卡迁移超限时原串保留；明确减少配置后可在原限制内再保存。

第三方属性不可用时，受影响卡全部分类暂停。优先恢复兼容提供者，让终端重新检查原规则；其他正常卡可用。“全部”是用户主动切换，不是异常自动放行。不要为消提示直接清空卡片。

## 卸载

1. 正常退出并完整备份世界、玩家/方块实体数据与配置，保留原 JAR 和可恢复环境。
2. 模组仍安装时，从各终端取回四卡，检查玩家、箱子及其他库存；取回并不会把卡变成原版物品。
3. 移除本模组会取消其物品/组件/菜单/配方注册。不要假定存档仍保留这些对象，也不要假定重装就能恢复已经丢失的数据。需保留卡片配置的世界应继续保留本模组，或完整备份后再卸载。
4. 两端同步调整，只在独立副本确认卸载后可加载。卸载属性提供者可能损坏它自身物品/方块，H4 不负责修复提供者自己的存档问题。
5. 分类记忆偏好文件为 `config/rs2multifilter-client.properties`，不保存服务端卡片配置；可备份，不需为了升级先删除。

## 回滚

恢复配套的世界副本、原 JAR 和配置。只换旧 JAR 不撤销后续存档写入，也不保证旧实现理解新状态。历史包内部同为 0.9.0-alpha，须以哈希区分，不混连；尤其不要用 H1—H4 之前的实现处理唯一异常卡。
